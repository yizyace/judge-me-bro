## Project orientation (read this first)

**Judge Me Bro** is a local-first, file-system-based AI judging system for
hackathons. The project is **specs-first** — implementation hasn't started yet,
so the documents in `specs/` are the source of truth. Read the relevant spec
before starting a task.

### Specs (`specs/`)

| Spec | Read it for |
|------|-------------|
| [`root.md`](./specs/root.md) | Master plan: pitch, goals/non-goals, architecture, repo layout, data model, pipeline, agents, skills, milestones. **Start here.** |
| [`judging-schemas.md`](./specs/judging-schemas.md) | Normative Phase 1 (idea judging) + Phase 2 (judge-to-judge) contracts: schemas, procedures, prompts, validation, evaluator math. |
| `persona-schema.md` _(planned)_ | Persona frontmatter contract. |
| `reputation.md` _(planned)_ | Reputation scoring math (Phase 3 aggregation). |
| `hosting.md` _(planned)_ | Deploy / upload API. |

### Citing schemas across specs

`judging-schemas.md` is the single source of truth for evaluation shapes. Cite a
contract by its stable label — `judging-schemas#<Schema>` (e.g.
`judging-schemas#IdeaEvaluation`) — instead of redefining it; the schema index
at the top of that file lists every label. When scoring math changes, bump the
`evaluator_version` (`eval@vN`) rather than editing in place, or
version-over-version reputation comparisons break.

### Gotchas (save a fresh agent some time)

- **Don't hand-edit generated files.** `CONSTITUTION.md` is dd-dm-generated
  ("DO NOT EDIT THIS FILE DIRECTLY"); change it via `dd-dm` commands. In *this*
  file, edit only between the `dd-dm:custom` markers — everything outside them
  is regenerated on `dd-dm pull`.
- **Evolve specs additively.** Prefer adding a normative sub-spec and pointing
  older sketches at it over rewriting in place — see how `root.md` §6.3/§6.4
  point at `judging-schemas`.
- **Commits & PRs.** Atomic + Conventional Commits per `CONSTITUTION.md`; open
  PRs against `main`.
